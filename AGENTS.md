# REP531 training log

## Requirements and workflow
Build a mobile-first offline React/TypeScript/Vite PWA. Use Dexie IndexedDB only; no accounts, backend, paid services or telemetry. Prepare GitHub Pages deployment from Windows, but do not deploy during development. Implement and test one domain feature at a time. Do not delegate unless explicitly requested. Keep calculations independent of UI and storage. Run `npm test`, `npm run build` and appropriate `npm run test:e2e` checks before handing off changes.

## Training rules
Four lifts default to squat, bench, deadlift and overhead press on Monday, Tuesday, Thursday and Friday. A cycle normally has four weeks, each containing four sessions in configured order. Optional settings.skipDeload makes it three weeks/twelve sessions; both settings.skipWarmups and skipDeload default false, including older backups. Week percentages: 65/75/85 with 5/5/5+; 70/80/90 with 3/3/3+; 75/85/95 with 5/3/1+; deload 40/50/60 with 5/5/5. Warmup: 40%x5, 50%x5, 60%x3. BBB defaults to five sets of ten at 50%. User-requested deload omits both warmup and BBB. TM = 90% of entered 1RM; allow direct TM overrides. Round calculated loads to nearest configured increment (5 lb or 2.5 kg by default). Plate loads are symmetric, use available pairs, and explicitly report unachievable loads. No silent TM increases between cycles; offer configurable increases and apply only when enabled. Cardio never advances lifting progress.

## Architecture and conventions
Use strict TypeScript, functional React components, descriptive names, and accessible labeled controls. Domain types/calculations in src/domain; persistence/backup in src/data; UI in src/components. Store one versioned state document in Dexie `state` table with id `main`: settings, cycle cursor, active workout, completed workouts and cardio. Serialize writes and restore atomically. Workout snapshots retain their own units, TM and prescribed sets. Validate all imports before replacing existing data. Reject unknown schema versions, malformed values and duplicates. Export complete JSON plus a human-readable timestamped Markdown history. Timer deadlines use wall-clock timestamps. Browser storage can be cleared/evicted: encourage downloadable backups and request persistent storage where supported.

## Equipment, variations and accessories
Settings keep separate `equipment.lb` and `equipment.kg` banks, with independent plate denominations. Assume an Olympic bar of 45 lb or 20 kg through equipmentForUnits; remove bar configuration controls. Retain legacy bar metadata in backups and historical workout snapshots, but never use it for new prescriptions. Unit changes must never convert or mutate either bank. Convert TMs against the destination bank and select the closest load achievable with identical plates on both sides and the configured total-load increment. For equal-distance ties, prefer the heavier load. Balanced available plates take priority over an impossible increment. Use integer-cent/GCD dynamic programming for exact loads and non-canonical plate inventories. Automatic warmup, main and BBB sets must also be loadable. With default kg plates 25/20/10/5/2.5 and a 20 kg bar, 225 lb snaps to 100 kg, with 40 kg per side. Converted accessory weights/increases use 5 lb or 2.5 kg steps without conversion noise.

Save Normal or BBB Swap independently in `settings.cycleVariants` by cycle number. Swap pairs squat/deadlift and bench/press, always using the supplemental lift's own TM. New unconfigured cycles default Normal. Capture variant, BBB lift and BBB TM in each workout snapshot. Deload and the BBB toggle still take precedence.

Accessories are a catalog categorized Push, Pull, Legs or Abs. Include ten push, ten pull and ten leg presets. Leg presets are Bulgarian split squat, Romanian deadlift, Leg press, Goblet squat, Walking lunge, Step up, Lying leg curl, Leg extension, Hip thrust and Standing calf raise, starting at editable 5 x 10 with zero load. Users choose one or multiple from any category per day; suggest a push, pull and legs/abs without enforcing counts. Deleting an exercise removes its assignments. Use each day's accessoryAssignments array order in generated workouts; allow drag/touch/keyboard reordering of selected accessories. Snapshot category and optional accessoryId on accessory sets (older sets without IDs remain valid). Group accessory workout rows under exercise headings; repeated rows represent sets, not different exercises.

Saving Settings or resuming an active workout must reconcile its accessories against selections for the workout's own main lift. Keep main/warmup/BBB prescriptions unchanged except when converting units. The selected preference controls units throughout the UI. Convert active workout weights, TMs, bar, plates and zero-set templates on Settings save, load and restore; preserve IDs, reps, completion and session set counts. Use destination Olympic bar/plate bank and rounding for barbell loads; use standard unit steps for accessories. Render historical details and Markdown exports in preferred units without mutating original history or JSON backup records. Charts convert their estimates into preferred units. The two equipment banks and intentional faint other-unit maxes remain visible in Settings. Preserve completed accessory sets, including deselected exercises, and retain manual weight/repetition edits for exercises still selected. Refresh untouched pending prescriptions, remove pending deselected sets, add missing selected sets, and convert weights into the workout's snapshot units. Match older name-only snapshots using the previous catalog name/category. Never automatically rewrite completed performance; explicit user corrections to date, weights, reps, completion and notes are allowed. Document that saving applies current accessories, while main program changes apply next session.

The Dexie table version remains 1, while the document/JSON data version is 3. Validate and migrate v1/v2 documents before writing upgraded state. Preserve old equipment in its original bank, initialize the other bank, preserve accessory day assignments and leave active/history set values untouched. Unknown versions and malformed migrations must fail without replacing saved data. JSON exports use v3; imports accept validated v1, v2 and v3. v3 adds settings.oneRepMaxes (nullable per lift), converts saved 1RMs with units, and seeds missing preset accessories. Preserve all previous day selections and workout snapshots.

Accessory set counts can be changed per active workout from zero through twenty without modifying catalog defaults. Add sets beside their exercise and copy its last weight/reps; remove the last unfinished set, preserving completed work. Keep zero-set exercise headings available for adding sets back. Store optional `workout.accessorySetOverrides` keyed by accessory ID (with legacy name/category fallback), containing count, position and an accessory set template. Preserve overrides through Settings reconciliation, resume, local autosave and JSON backup/restore. Validate metadata before restore; older v3 snapshots without it remain valid. History is read-only until Edit workout is selected; use an isolated draft with Save changes and Cancel edits.

Workout rows use two compact lines beside weight, reps and completion controls: set number and prescription inline, then plates per side. Combine repeated plate denominations (for example, `2 × 25 + 10 + 5 lb`). Reduce section spacing while keeping readable inputs and 44px touch targets.
